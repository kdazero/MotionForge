# 關節、膚色與遮擋：0.3.1 的共用組裝流程

這些功能屬於角色組裝與渲染，與揮手、思考的角度曲線分開。修正同一角色的組裝後，所有動作都使用相同修正；不要為了接合手臂而鎖死手腕、改變動作節奏或拉長肢體。

## 第一次使用揮手與思考

要立即重播完整角色，先 `instantiate_motion_recipe`，再使用回傳的 `render_requests`。原配方 `female_gestures_v1` 保留 V3.9／V3.6 的完整骨架、手型和時序。`apply_motion_recipe` 只接受素材、骨架與網格都符合的角色，不會把另一個角色誤判為可直接套角度。

換成自己的角色，必須提供乾淨分件與可量測的關節。下列步驟是共同前置作業，不是要求使用者自行重寫兩個動作。工具能驗證明確的幾何、顏色樣本及遮擋規則，不能從任意圖片保證推斷正確人體，也不能補出原圖遮住的衣服。

## 1. 完整保留衣服

`extract_part.mask.required_polygons` 指定這個部件必須保留的原圖區域，例如手臂抬起後會露出的背心外緣。座標使用原圖像素。若切圖輪廓、排除區或皮膚篩選裁掉其中的不透明像素，工具會停止並回傳缺失範圍，不能當作成功部件繼續組裝。

只圈衣服中央無法保護外緣；請包含完整服裝，避開最外側抗鋸齒的半透明像素。`required_polygons` 不會自動補繪，也不會替使用者猜測服裝邊界。

`extract_part.mask.forbidden_polygons` 指定屬於其他分件、不可殘留的區域。例如軀幹切圖不可帶著旁邊的白袖口；即使殘片仍連在軀幹上、通過連通檢查，也會被拒絕。這是驗證條件，請另外修正 `polygon` 或 `excluded_polygons`；不會悄悄擦掉原圖。必要與禁止區域都必須依原圖的實際邊界量測，不能把袖子誤標成應保留的背心。

短袖的內側縫線應接在胸部，外側和袖口隨上臂移動。使用 `bind_mesh` 時，沿實際袖窿縫線配置胸部權重，向外漸變至上臂權重；只按圖片高度分配權重，會讓整段腋下縫線隨上臂拉開。分別檢查軀幹、袖子、皮膚的單獨圖層，再檢查合成後的靜止與抬手畫面。

## 2. 以腕根、腕寬和方向註冊手型

用 `register_joint_attachment` 代替猜測 PNG 中心位移。必要參數：

- `source_edges`：手圖腕根截面的兩端，來源圖片像素，原點左上、Y 向下。透明留白包含在此座標內。
- `target_edges`：角色腕根截面的對應兩端，槽位骨骼局部座標，Y 向上。順序須與來源一致；兩端交換會改變手的方向。
- `source_sample`、`reference_sample`：皮膚內部的 `[x,y,width,height]` 取樣框，避開深色輪廓、衣服及透明邊緣。
- `reference_slot`、`reference_attachment`：這個角色自己的未校色前臂部件。
- `root_fade`、`tip`：可選的腕根重疊羽化寬度與朝向掌部的點，都使用手圖像素。羽化區下方必須有完整前臂，不能用羽化掩蓋缺失素材。

工具根據兩對端點求出位置、旋轉與等比例尺寸，並以兩個皮膚區域的中位數計算 RGB 校正。過暗、透明、越界或差異過大的取樣會被拒絕。PNG 原檔不變；校正保存在附件，所有輸出格式使用同一渲染結果。這是局部膚色校準，不會修正錯誤指型、光源方向或線稿畫風。

## 3. 裸露肘部使用連續皮膚

用一張從袖口下方延伸到手腕的完整皮膚切圖，呼叫 `bind_joint_strip`。不要在裸露肘心把上下臂切成兩個圓頭再相疊，這會露出輪廓線和不同陰影。

`parent_bone`／`child_bone` 必須為直接親子骨；`start`／`end` 指定皮膚沿肢體方向的起終點，採切圖像素座標；`blend_width` 是骨架 setup 的世界單位。`rigid:true` 使用保持旋轉厚度的混合；骨骼含缩放時應明確選用 `rigid:false`。`tip_bone` 可指向關節的後代掌部骨，保留掌心翻轉的小幅縮放。

自動網格涵蓋透明輪廓的凸包並提供連續關節權重。較大的混合範圍不一定更好：深彎時可能自交、產生小孔或不自然外形。務必檢查抬手途中、最大彎曲、腕部極限及放下的畫面，依實際肢寬校準；不能僅憑「沒有分件切口」判定美術合格。

網格會保留輪廓凸包的轉折列，避免均勻取樣略過斜向袖口、把原本完整的皮膚削掉。`rows` 是密度目標；必要轉折較多時會增加至最多 48 列。超過可容納的轉折數會明確失敗，需先整理分件輪廓。這個修正影響新建網格；舊工程要以保留的原始 region 分件重新執行 `bind_joint_strip`，才會更新頂點。

## 4. 用槽位名稱設定遮擋

`set_layer_constraints` 接受 `[後方槽位, 前方槽位]` 的清單，例如 `["head", "hand_left"]`。規則會在每個動作的 `drawOrder` 之後套用，因此手指靠近下巴時不會被原本排在最後的頭部蓋掉。可另設 `["lower_cuff", "hand_left"]`、`["hand_left", "upper_cuff"]`。

不存在的槽位、循環遮擋和過期修訂會被拒絕。規則適用整個角色；需要前後切换的物件仍應設計獨立槽位／明確動作層序，而不是建立互相衝突的固定規則。完成後才 `lock_identity`，鎖定圖層規則、附件校色和原圖素材。

## 驗證與相容性

渲染與匯出仍需逐格檢查。自動測試涵蓋不同透明留白和方向下的對位、渲染後皮膚顏色、連續彎肘、不透明衣服覆蓋，以及動作層序變更後的手／臉遮擋。

`rgbGain`、`rootFade`、`jointRegistration`、`layerConstraints` 是 MotionForge 的擴充資料；PNG／WebP／APNG／GIF 已套用這些效果。直接把骨架 JSON 交给其他遊戲引擎，不保證支援這些擴充。原有配方沒有這些欄位時，渲染結果維持相容。美術檢查與使用者驗收仍分開記錄。
