# 如何提供動作參考

MotionForge 的動作流程是「使用者提供參考 → AI 讀取並理解 → AI 編寫骨架與附件軌道 → 渲染 → 使用者回饋」。目前沒有影片轉骨架或動作捕捉模型。

## 提供哪些資料？

| 資料 | 建議提供方式 |
| --- | --- |
| 影片／GIF | 提供給 AI 客戶端，指定第幾秒到第幾秒 |
| 網路連結 | 附時間段；AI 需先確認能開啟並看到內容 |
| 姿勢圖片 | 編號 01 起手、02 主姿勢、03 收尾，必要時補中間姿勢 |
| 文字 | 動作部位、左右方向、次數、速度、情緒、總長、循環與收尾 |

左右請明確寫「角色自己的右手」或「畫面右側」，不要只寫「右邊」。指定影片只參考手腕時，也應說明是否保留原站姿、表情與鏡頭。

若影片連結看不到，AI 應說明缺少哪段資料，請使用者提供可讀取的影片或截圖，不可自行聲稱已看過。MotionForge 的 `upload_asset` 支援 PNG/JPEG/WebP/JSON，**不支援 MP4 或 GIF 動作解析**；影片應留在具備讀取能力的客戶端。

## 需求範例

> 請用我的角色製作 4 秒揮手。參考附件影片 2～5 秒，只模仿角色自己的右手和手腕節奏；抬到臉旁揮四次，最後自然放回。不跟隨鏡頭，不改衣服，表情微笑。先給透明 WebP 草稿，確認後再輸出 PNG 序列。

完整表格見 [需求表](../examples/motion-request.md)。不需要使用者填骨架角度或座標。

## AI 應先回覆什麼？

開始製作前，整理：

1. 實際查看的資料與時間段。
2. 起手、主要動作、停頓與收尾的時間安排。
3. 要保留的外觀與不採用的鏡頭動作。
4. 是否缺少手心、側臉或遮擋部件；補圖由誰提供。
5. 輸出長度、循環、畫布、格式，以及尚不確定的地方。

再使用 `set_animation` 編寫動作，`start_render` 的 `spec.references` 可保存最多 20 筆字串欄位的來源紀錄。這些紀錄會進入素材包，因此不要放入存取憑證、私人分享權杖或不希望接收者看到的連結。

```json
{
  "references": [
    {
      "source": "使用者提供的 reference-wave.mp4，由 AI 客戶端讀取",
      "time_range": "00:02–00:05",
      "focus": "角色右手、四次揮動與手腕延遲",
      "exclude": "鏡頭縮放、背景和原角色外觀",
      "observation": "填入實際看到的動作，不以範例文字冒充已觀看"
    }
  ]
}
```

這是 `RenderSpec` 中的欄位範例，不是獨立上傳影片的指令。AI 客戶端實際傳入 `start_render` 時，另需 `project_id` 與 `animation`。

## 如何提出修改？

用動作時間與部位描述，例如「第 1 秒手再高一點」「最後放下太快，延長半秒」「第三下手腕不要翻面」。AI 應保留之前版本，更新動作後重新渲染與檢查。

參考資料與可再散布的範例素材分開處理。開源專案只附本專案程式繪製的機器人；使用者的影片、角色與第三方素材仍依原有權利和授權使用。
